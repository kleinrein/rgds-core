RG DS boot artwork, generated by tools/build_boot_assets.py. The dual-screen
emblem matches the native launcher scene; the wordmark uses assets/brand/.
No vendor or Nintendo artwork is used.

logo.bmp: 640 x 480, uncompressed 24-bit BMP, top-down rows for U-Boot/kernel.
logo.png: the same RGB pixels for existing userspace boot logo files.
waiting.bmp: 330 x 50, uncompressed 24-bit BMP, for the vendor waiting renderer.

animation.rga: 36 pre-rendered 640 x 480 BGRA frames at 18 fps, compressed with
zlib; regenerate with python3 tools/build_boot_animation.py after static art.

The firmware slots are static images. The separately installed early KMS
service starts after device discovery and animates both panels during normal
startup. Before Weston starts, it releases DRM master but retains and updates
its scanout buffer until both CRTCs replace it. It does not wait for an
animation to finish. Once the launcher owns the displays, its native scene
animates the screen glass, hinge and orbiting pixels.
The welcome screen continues on a fresh touch, A or Start at any point.
Disabling UI animations keeps launcher/welcome feedback static. The separately
installed early service can be removed with boot_splash_install.py remove.
