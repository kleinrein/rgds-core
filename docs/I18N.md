# Languages

Settings → System → Language selects English (US), Bahasa Indonesia, Dansk,
Deutsch, Español, Français, Italiano, Nederlands, Norsk bokmål, Norsk nynorsk,
Polski, Português (Brasil), Português (Portugal), Suomi, Svenska, Tiếng Việt,
Türkçe, Русский, Українська, 日本語, 简体中文 or 한국어. English comes first; the
other languages are sorted by their native names, so Cyrillic follows Latin and
the CJK languages come last. Swipe the list, drag or tap
the shared rounded scrollbar, use the mouse wheel,
or use the D-pad to move through every language. Scrolling keeps the focused
option visible and does not apply it; tap a row or choose Apply to save.
The selection is stored as `language` in the existing `ui.ini` and shared by the launcher and
in-game menu. Missing settings retain English. Changing language takes effect
immediately in the launcher and on the next opening of the in-game menu.

To add a language:

1. Copy `assets/locales/en-US.tsv` to a new file named for its language tag.
2. Keep each first column unchanged and translate the second column. Separate
   columns with one literal tab; use UTF-8 and one message per line.
3. Preserve `{0}` placeholders exactly. They carry dynamic values such as a
   game count or emulator name; they can move within a translated sentence.
4. Add the language tag and native name to `assets/locales/languages.tsv`,
   separated by a tab. Keep English first and sort the remaining native names.
   No launcher code change is necessary for registration.
5. Run the catalog checks in `tests/test_core_upgrade.py` and
   `tests/test_core_refinement.py`, plus the gesture checks in
   `tests/test_language_picker.py`. Build and inspect both screens, long labels,
   confirmation dialogs and all game-menu pages.

The first column is stable English source text. Unknown messages fall back to
that text. Game titles, ROM filenames, network names and user input are data,
not translation keys. External engine or system diagnostic text can also fall
back to its original language.

The pixel renderer supports Latin accents, ß and Bokmål Æ, Ø and Å, including
lowercase input. Vietnamese precomposed letters preserve both their vowel shape
and tone marks in the pixel typeface. Polish and Turkish letters draw as a base
letter plus ogonek, acute, dot, breve, cedilla or stroke; Cyrillic capitals with
a Latin twin reuse it and the rest have their own 5×7 shapes in
`src/launcher/pixel_text.hpp`. The bundled rounded font's Nunito source covers
the Latin, Vietnamese, Latin Extended-A and Cyrillic glyphs, baked into all five
font sizes (`rounded-N.rgf`) by `tools/bake_font.py`. Pillow 13 reproduces the
shipped atlases byte for byte; older Pillow releases shift glyph bounds, so bake
with Pillow 13 or later (the baker also needs fontTools).

## Japanese, Chinese and Korean

CJK text comes from a second font family per language, five atlases each:

| Family | Language | Source (tools/fonts) | Holds | Glyphs | Size |
|---|---|---|---|---|---|
| `rounded-ja-N.rgf` | ja-JP | M PLUS Rounded 1c Medium | kana, halfwidth katakana, 2,965 JIS X 0208 level-1 kanji | 3,357 | 13 MB |
| `rounded-zh-N.rgf` | zh-CN | Noto Sans SC, weight 500 | GB 2312 symbols, 3,755 level-1 hanzi | 4,139 | 17 MB |
| `rounded-ko-N.rgf` | ko-KR | Noto Sans KR, weight 500 | compatibility jamo, 2,350 KS X 1001 hangul | 2,602 | 10 MB |

Each family also holds the CJK symbols, full-width forms and every character of
its own catalog. The national sets cover everyday text and most game titles.
The source fonts sit in `tools/fonts`, outside the shipped app (the Noto files
are subset instances; see `assets/fonts/source/PROVENANCE.txt`), so only the
atlases and licences ship; compressed, the three families add about 14 MB to a
release.

The launcher only consults a family for codepoints from U+2E80 up that the Latin
atlas lacks, and reads a family's atlas for a size the first time one of its
glyphs is drawn, so other languages never load it. Boot verification skips
family atlases for the same reason; they are verified with the release. Each
glyph is copied into a 1024×1024 cache texture per size on first use, so the GPU
never holds a whole atlas. `RoundedFont::prefer` puts the interface language's
own family first (ja, zh or ko), so Han characters shared by Japanese and
Chinese take that language's shapes; the other families still fill gaps, such
as a simplified hanzi in a game title under the Japanese interface.

To add another CJK family:

1. put its source font and licence in `tools/fonts`, copy the licence to
   `assets/fonts/source/` and add a `PROVENANCE.txt` entry;
2. add a `FAMILIES` entry in `tools/bake_font.py` (source, base character set,
   catalog) and bake with Pillow 13 and fontTools; the existing atlases must
   come out byte-identical;
3. add the family to `families` in `tests/test_core_refinement.py` and, if its
   language code is new, to the order in `RoundedFont::prefer`;
4. write the catalog as above.

Wrapped labels break at spaces and, for Japanese and Chinese, between any two
characters (`src/launcher/line_break.hpp`), except before closing punctuation,
small kana and the long-vowel mark, or after an opening bracket. Korean is
written with spaces and wraps at them. The pixel typeface has no CJK shapes:
such characters draw from the rounded family, centred in a two-cell box on the
pixel baseline, and every pixel-width calculation counts them as two cells.

Scripts that need shaping or right-to-left layout (Arabic, Hebrew, Hindi, Thai)
are not supported by either renderer.
