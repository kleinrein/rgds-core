# RGDS startup, hardware services and emulator review — 2026-10-09

The offline review found and corrected faults in independent-mode menu context,
Wi-Fi recovery, charge indication, community-controller decoding and suspend
completion. Configurable fast-forward input is implemented. **Physical boot and
hardware acceptance remain pending.** SSH to the last recorded RG DS address
timed out; this work did not deploy, reboot, suspend or flash the handheld.

## Findings and corrections

| Area | Finding | Correction |
| --- | --- | --- |
| In-game power/display | The menu's cleaned environment dropped independent mode, panel names and lid wake paths. It could choose stock helpers or the wrong displays. | Preserve the session's hardware context and pass named top/bottom displays to the menu. |
| Suspend/resume | `systemctl suspend` acknowledges enqueue, not completion of the sleep/wake cycle. Resume handling could run too early. | Install an owned system-sleep hook and wait for this request's matching post-resume token while retaining the hardware lock. Reject stale tokens, failed enqueue and missing start acknowledgement. No raw kernel-state write. |
| Wi-Fi | Missing-adapter recovery still entered a stock helper from the independent OS. | Independent mode uses kernel/NetworkManager initialization and a bounded adapter wait; report a missing driver without invoking vendor initialization or resetting a PHY. |
| Battery/charging | `Full` triggered the charging animation; missing `capacity` could hide valid charging state. | Separate active charging, external power and charge percentage. Full/attached power gets a static plug; active charging animates. Read charge/energy counters when capacity is absent. |
| Community controller | The known `retrogame_joypad` name fell into a different menu/Start evdev layout. | Recognize that console layout in the menu observer and direct NNDDSS input translation. Its actual device calibration still needs acceptance. |
| Startup | NetworkManager's wait-online unit could prolong normal boot completion. | Disable it in new image assembly alongside networkd/wait-online. The console units depend on seatd/Weston, with no Wi-Fi/online target or ROM scan dependency. |

The suspend correction follows [systemd 257's documented asynchronous suspend
behavior](https://github.com/systemd/systemd/blob/v257/man/systemctl.xml).
The owned hook proves that the OS reached its post-sleep callback; physical wake,
driver restoration and a successful real suspend still need the device/logs.
An image without that hook does not advertise independent sleep support.

## Fast-forward controls

Settings → Controls, cartridge Controls and the in-game Controls page now offer
**Fast-forward button** and **Fast-forward style: Hold / Toggle**. Global and
per-game profiles share the existing inheritance and live-refresh mechanism.
Assigning a button transfers any conflicting DS binding, so one press does not
also become a game action. Restore defaults clears the speed binding.

Hold mode releases on menu entry, profile changes, input loss and dropped event
synchronization. Toggle mode changes once per press, ignoring repeats. The speed
request uses a separate small command file, preserving an outstanding checkpoint
or menu command. Each engine starts at normal speed; the menu reads the bridge's
current requested speed state.

| Engine | Adapter | Remaining validation |
| --- | --- | --- |
| DSperate | Pinned source's native Tab toggle; immediate down/up pairs let short holds return to normal. | Actual acceleration, audio and menu/resume on RG DS. |
| NNDDSS | Its verified loader's native Tab toggle. Disable the former fixed physical fast-forward binding to keep state under shared controls. | Actual acceleration, shader/audio restoration and touch under fast-forward. |
| DraStic | Owned virtual joystick button 19, mapped to `CONTROL_INDEX_FAST_FORWARD` in both config banks; normal startup speed. | Proprietary executable is still missing locally. Validate its native toggle behavior, Hold conversion and audio with the owner's application. |

Host checks establish input routing and dispatched native actions. The bridge's
speed state is not measured game FPS or proof of acceleration. No multiplier is
promised; retain correct DS timing at normal speed.

## Startup evidence

The default independent boot has no Touch to continue wait. It waits only for an
active compositor socket, polling every 20 ms with a 10-second failure deadline;
that deadline is not a mandatory delay. Startup hashes launcher/runtime/theme
inputs while deferring engine archives. Library scanning and deferred work start
after the first presented frame. Existing integrity and recovery checks remain.

Five current host runs measured first-presentation acknowledgement at
246.318, 21.532, 22.858, 22.345 and 22.417 ms: **22.417 ms median, 246.318 ms max**.
Raw results: `build/review-startup-benchmark-20261009.json`.
This uses SDL dummy rendering on the Mac and excludes Linux/kernel/compositor,
real panel/input drivers, Python dispatch and power-button time. The first sample
was slower; do not present the median as guaranteed console boot time or a
measured improvement over Anbernic. First-boot resizing and SSH-key generation
also need separate timing from steady-state cold starts.
