# Settings and shader studio rebuild — 2026-10-08

This rebuild is entirely host-side. No device connection, deployment or hardware test was performed.

## Settings and in-game menu

General settings and game settings share original vector icons, single-line cards, visible values/switches, readable light/dark layouts and generous touch targets. All existing display, sound, power, library, artwork, connectivity, system, startup and recovery actions remain available. Controls adds button capture and profile management. The in-game menu contains ten actions, including Controls, in a three-column grid below Resume.

Typography scales from the five bundled font atlases. Requested sizes use consistent scaled measurements/advances/bearings; additional sizes do not create additional atlases or texture families. Pixel classic remains available. Both themes/fonts were reviewed in host screenshots.

## Shader studio

Sunlit Grove, Neon Circuit and Starfall Port are original pixel scenes generated by repository code. Each is rendered at 640×480 through Off and all 14 actual GLES presets. The native scene is 256×192, so the references exercise fractional 2.5× scaling rather than hiding Sharp bilinear differences with an integer scale.

The top screen shows a comparison, magnified pixel detail, scene and effect description. X / Scene selects a reference, Y / Compare cycles Original / Filtered / Split, and L/R or desktop brackets moves the split. Browsing changes the preview; Apply saves the choice and uses live engine acknowledgement in game. Focus, scene, comparison mode and split survive preview restart.

The 45 lossless RGSP references total 2,936,440 bytes rather than 55,296,000 bytes of raw RGBA. The decoder validates its tile atlas and indices without additional dependencies. The runtime caches at most eight textures/10 MB. Asset warming and adjacent-preset prefetch happen before drawing; drawing/detail rendering perform no file reads or stats. The package validator verifies exact asset inventory, native PNGs, packed/decoded pixel hashes, source shader hashes and pipeline provenance using the Python standard library.

Regenerate references on a host with EGL/GLES2 and Pillow using `python3 tools/build_shader_previews.py`. Normal packaging uses the bundled references and requires no graphics driver or Pillow to verify them.

## Controls and shortcut

Controls profiles are stored in `userdata/controls.ini` and optional `userdata/library/<game-key>/controls.ini`. Game overrides can inherit global choices. Default, A/B swapped and left-handed presets cover all 12 DS buttons/directions; custom bindings accept the face/shoulder/start/select/directional buttons, L2/R2/L3/R3, or unassigned. Capturing a reused physical input swaps its previous assignment. Navigation in the launcher/settings stays unchanged.

SDL joystick/controller events and polling apply the canonical mapping once. NNDDSS direct input routes retain touch calibration and avoid remapping the SDL evdev stream twice. Used auxiliary inputs are removed from their original fast-forward/stylus/screen-toggle roles. Native DSperate/DraStic input configuration is managed consistently; unrelated tuning and battery saves are retained. Profiles refresh in the bridge while playing.

The default home shortcut is **Start + Anbernic pressed together**. A lone Anbernic press opens the shared pause menu. Home uses the existing save-before-exit protocol; a failed save retains the game and overlay for retry/resume. Input ledgers clear held event state on menu entry, chord activation and profile changes, and drop stale menu inputs on resume.

Host checks cover actual App capture, swapping/unassignment, global/game scopes, inheritance/reset, cancellation, failed writes, shader pixels/comparison controls, caching, source validation, game event/poll routes, chord ordering, neutral releases and failed-save protection. Final results and artifact identity are recorded in `build/settings-rebuild-validation.json`. Physical controls, remapped gameplay and hardware rendering remain for the later authorized device session.

## Interaction refinement

Settings cards now use single-line titles, plain page headings and a back target in the header. Pixel classic uses smaller integer glyph scales for card titles and captions. Scrolling supports vertical finger swipes and a 32-pixel-wide rail with a textured accent thumb, hover highlight and an 80 ms drag cue. Grabbing the thumb preserves the contact offset. Settings taps commit on release; swiping or losing focus cancels the pending tap.

Emulator, power, idle-sleep, startup, control-profile/layout/shortcut, resolution and frameskip choices open a panel with every alternative and a checkmark on the saved value. Left/right, up/down and A work immediately; A or a direct tap applies, B cancels. The panel travels only 10 pixels over 90 ms; switches settle in 90 ms. Disabling animations bypasses these cues without changing interaction or persistence.

Mute clears slider-key repetition. Duplicate mouse events following physical/SDL touch are suppressed, and SDL touch on the device routes to the lower panel even when KMS associates it with the upper window. Direct touch also accepts Type-A coordinate-only contacts. Host regressions cover gesture cancellation, swipe scrolling, scrollbar grab offset, choice cancellation/application, duplicate mute delivery and persisted mute. Hardware touch and audible mute still need a physical device check.

LCD border strength is reduced in the shared GLES pipeline: LCD1x scanline/LCD brightness parameters are 32/14 (previously 16/4), and zfast border strength is 5 (previously 14). Colour-only and sharp-bilinear presets retain their original transforms. All 45 references were regenerated through the same pipeline; the enlarged inset is explicitly labelled “Magnified detail”. These are visual tuning choices, not measured panel calibration.

Refinement validation: current host and AArch64/glibc 2.17 builds succeeded. The 543-test suite passed 541 tests on its first run; two legacy input sequences were updated for explicit choice confirmation and passed in the final 20-test focused run. The additional queued-zero-volume test, shader provenance validation and launcher self-test passed. Results are recorded in `build/ux-review/validation.json`; no device deployment occurred.

## Quiet upper-panel revision

Ordinary settings pages now show only a small muted icon and page title on a plain upper panel. Moving focus or changing a value on the lower panel leaves that composition unchanged. The settings overview stays on “Settings” while browsing categories; it changes title only when a page is opened. Both screens omit the extra Settings breadcrumb/subtitle. Descriptive copy, summary cards, decorative texture, upper-panel entrance motion and permanent advice notices (including Available offline) are removed. Shader previews, active button-capture instructions, scraper progress and operational errors remain visible when relevant.
